# ข้อมูลจำลองสำหรับเทรนและวัดผลโมเดล (datasheet)

ไฟล์ในโฟลเดอร์นี้สร้างจาก `ml/app/synthetic.py` ด้วย seed คงที่ รันซ้ำได้ข้อมูลเดิมทุกไบต์
สร้างใหม่ได้ด้วย `cd ml && python -m app.benchmark --export data/synthetic`
รายละเอียดพารามิเตอร์ทุกตัวของแต่ละชุดอยู่ใน `datasets.json`

**ข้อมูลทั้งหมดเป็นข้อมูลจำลอง** ไม่มีข้อมูลของผู้ค้าจริง ใช้เปรียบเทียบจุดแข็งจุดอ่อนของโมเดล ไม่ใช่ตัวแทนความแม่นกับตลาดจริง

## ความเสี่ยงจ่ายช้า (`risk_*.csv`)

หนึ่งแถวต่อบิลรายเดือนที่รู้ผลแล้ว ฟีเจอร์คิด ณ วันออกบิลด้วยโค้ดเดียวกับระบบจริง (`features.risk_features`, `risk.build_dataset`)
บิลที่ยังไม่ถึงกำหนด ณ วันอ้างอิง (1 ต.ค. 2569) ไม่อยู่ในไฟล์ เพราะยังไม่รู้ผล

| คอลัมน์ | ความหมาย |
|---|---|
| `bill_id`, `due` | เลขบิลจำลอง และวันครบกำหนด |
| `late_count` | จำนวนครั้งที่จ่ายช้าใน 6 บิลล่าสุด |
| `avg_days_late` | จำนวนวันที่ช้าเฉลี่ยต่อบิล (6 บิลล่าสุด) |
| `bill_ratio` | ยอดบิลนี้ ÷ ค่าเฉลี่ย 3 บิลก่อนหน้า |
| `tenure_years` | ระยะเวลาที่เช่ามา (ปี) |
| `stall_type`, `season` | ประเภทแผง และฤดูของวันครบกำหนด |
| `n_prior` | จำนวนบิลก่อนหน้าที่ใช้คิดฟีเจอร์ (สูงสุด 6) |
| `label` | 1 = จ่ายหลังวันครบกำหนด หรือเลยกำหนดแล้วยังไม่จ่าย |

กลไกการจ่ายช้า (เหมือนตัวสร้างข้อมูลสาธิต `api/src/seed/generator.js`):
`logit = ฐาน + 4.2·(0.5 − วินัย) + 0.3·ครั้งที่ช้า + 2.2·(ยอดบิล/ปกติ − 1) + ประเภทแผง + ฤดู + ระยะเวลาเช่า + สุ่ม`
แต่ละชุดปรับตัวคูณบางพจน์ (`k_*`) ดู `datasets.json`

| ไฟล์ | สถานการณ์ | แถว | จ่ายช้า |
|---|---|---|---|
| `risk_baseline.csv` | ตลาดปกติ เหมือนข้อมูลสาธิต | 433 | 39% |
| `risk_noisy.csv` | พฤติกรรมสุ่มมาก สัญญาณอ่อน | 437 | 33% |
| `risk_rare_late.csv` | จ่ายช้าน้อย (ข้อมูลไม่สมดุล) | 420 | 10% |
| `risk_seasonal.csv` | ฤดูกาลมีผลแรง 3 เท่า | 455 | 37% |
| `risk_bill_shock.csv` | ยอดบิลพุ่งทำให้จ่ายช้า | 440 | 31% |
| `risk_new_market.csv` | ผู้ค้าใหม่จำนวนมาก ประวัติสั้น | 254 | 33% |
| `risk_large.csv` | ตลาดใหญ่ 120 ราย 24 เดือน | 2,449 | 36% |

### ชุดที่ออกแบบให้โมเดลต่างกัน

ชุดเหล่านี้ใส่ความสัมพันธ์ที่โมเดลหนึ่งควรได้เปรียบ แล้ววัดว่าจริงไหม (สมมติฐานอยู่ใน `datasets.json` ช่อง `expect` และ `hypothesis`)
ผลรายพับของ 5-fold CV ทุกโมเดลใช้พับเดียวกัน จึงตัดสินด้วย paired t-test (t ≥ 2.776 ที่ระดับ 0.05) ต่างกันน้อยกว่านั้นถือว่าสรุปไม่ได้

| ไฟล์ | สถานการณ์ | แถว | จ่ายช้า | คาดว่าชนะ (ตัวชี้วัด) | เหตุผล |
|---|---|---|---|---|---|
| `risk_interaction.csv` | ยอดบิลส่งผลกลับทางกัน | 1,013 | 30% | Random Forest (CV AUC) | บิลสูงทำให้ผู้ค้าใหม่ช้าแต่ผู้ค้าเก่าตรงขึ้น ผลรวมเชิงเส้นเป็นศูนย์ |
| `risk_u_shape.csv` | ยอดบิลผิดปกติทั้งสองทาง | 1,276 | 19% | Random Forest (CV AUC) | ความสัมพันธ์รูปตัว U เส้นตรงลากได้ทางเดียว |
| `risk_type_season.csv` | ประเภทแผงช้าคนละฤดู | 1,557 | 23% | Random Forest (CV AUC) | ต้องดูประเภทกับฤดูคู่กัน ไม่มีพจน์ร่วมในโมเดลเส้นตรง |
| `risk_linear_small.csv` | ข้อมูลน้อยแต่ตรงไปตรงมา | 91 | 48% | Logistic Regression (CV Brier) | ข้อมูลน้อย โมเดลเส้นตรงให้ความน่าจะเป็นนิ่งกว่า |

ผลในรอบที่สร้างเอกสารนี้: สามชุดแรก Random Forest ชนะชัด (t 8–24) ส่วนชุดข้อมูลน้อย "สรุปไม่ได้" (t −0.9)
ซึ่งเป็นข้อค้นพบในตัว: ข้อมูลไม่ถึงร้อยแถวแยกสองโมเดลนี้ไม่ออก

## ค่ามิเตอร์ (`meters_*.csv`)

หนึ่งแถวต่อแผงต่อเดือน 35 แผง × 24 เดือน ค่าผิดปกติถูกใส่ไว้โดยรู้คำตอบ จึงวัด precision/recall ของการทักได้

| คอลัมน์ | ความหมาย |
|---|---|
| `stall_id`, `type_code`, `period` | แผงจำลอง ประเภท และรอบเดือน |
| `use_water`, `use_elec` | หน่วยน้ำ/ไฟที่ใช้ในเดือนนั้น |
| `label` | 1 = ค่าผิดปกติที่ใส่ไว้ |
| `kind` | `normal`, `high_water`, `high_elec` (ใช้มากผิดปกติ เช่น ท่อรั่ว), `low_water`, `low_elec` (น้อยผิดปกติ เช่น มิเตอร์เสีย), `pattern` (น้ำกับไฟขยับสวนทางกัน) |

| ไฟล์ | สถานการณ์ | ค่าผิดปกติ |
|---|---|---|
| `meters_baseline.csv` | ผิดปกติชัดเจน 2.5–4 เท่า หรือเหลือ 5–30% | 4.3% |
| `meters_subtle.csv` | ผิดปกติแนบเนียน 1.4–1.9 เท่า หรือเหลือ 40–60% | 3.5% |
| `meters_noisy.csv` | การใช้ปกติแกว่ง ±30% | 4.4% |
| `meters_seasonal.csv` | ฤดูกาลแรง หน้าร้อนใช้ไฟเกือบเท่าตัว | 5.0% |
| `meters_many.csv` | ค่าผิดปกติมาก ประวัติปนค่าผิดปกติ | 10% |
| `meters_pattern.csv` | น้ำกับไฟขยับสวนทางกัน 1.25–1.35 เท่า การใช้ปกติแกว่ง ±3% · **คาดว่าวิธีที่มี Isolation Forest ชนะ (F1)** | 3.5% |
| `meters_growth.csv` | 40% ของแผงโตเดือนละ 4% (ไม่ใช่ค่าผิดปกติ) · **คาดว่า Isolation Forest ชนะ (F1)** เพราะ z-score ทักร้านที่โต | 3.8% |

มิเตอร์ไม่มี CV (แบ่งตามเวลา) จึงตัดสินว่า "ต่างจริง" เมื่อ F1 ห่างกันอย่างน้อย 0.05

## วิธีวัดผลที่ใช้ในระบบ

ผลวัดถูกเก็บในตาราง `model_evaluations` และแสดงในแท็บ "ทดสอบหลายชุดข้อมูล" ของหน้าเบื้องหลัง AI (บัญชีทีม/กรรมการ)
- ความเสี่ยง: Logistic Regression, Random Forest และเกณฑ์อ้างอิง "เดาตามสัดส่วน" · แบ่ง 75/25 แบบ stratified + 5-fold CV · เกณฑ์ 0.5
  "ดีที่สุด" ของแต่ละชุดดูจาก CV AUC เฉลี่ย (นิ่งกว่าชุดทดสอบ 25% ชุดเดียว) · เก็บ CV Brier ด้วยสำหรับดูความตรงของความน่าจะเป็น
- มิเตอร์: z-score (เกณฑ์ 3), Isolation Forest (เกณฑ์ 0.62) และใช้ทั้งสองวิธี · เทรน 60% ช่วงแรก วัดผล 40% ช่วงหลัง
